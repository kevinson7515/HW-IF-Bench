## 修改内容

`django/core/mail/message.py` 中的 `sanitize_address`（保持 `email.headerregistry` 解析架构不变），共三处加固，全部将“崩溃或静默通过”转为清晰的 `ValueError`：

```python
            nm = token.display_name or ''
            localpart = token.local_part
            domain = token.domain or ''
            # A mailbox without a local part (e.g. "A name <>") is invalid.
            if localpart is None:                      # ① 新增
                raise ValueError('Invalid address "%s"' % addr)
    else:
        nm, address = addr
        if '@' not in address:                          # ② 新增
            raise ValueError('Invalid address "%s"' % address)
        localpart, domain = address.rsplit('@', 1)

    address_parts = nm + localpart + domain            # ③ 新增
    if '\n' in address_parts or '\r' in address_parts:
        raise ValueError('Invalid address; address parts cannot contain newlines.')
```

**修复的三个缺陷**（均已实测复现）：
1. **`'A name <>'` → `AttributeError: 'NoneType' object has no attribute 'encode'`**。`parser.get_mailbox('A name <>')` 解析成功但 `token.local_part` 为 `None`，随后 `localpart.encode('ascii')` 崩溃。注意用 `is None` 而非 falsy 判断：`'""@example.com'`（合法的空引号本地部分）必须继续接受，与真实 Django 行为一致。
2. **元组无 `@` → `ValueError: not enough values to unpack`**。`('A name', 'noatsign')` 在 `rsplit('@', 1)` 处给出误导性错误，现在是 `Invalid address "noatsign"`。
3. **换行注入静默通过**。`('na\nme', 'to@example.com')` 之类含 CR/LF 的部件此前会进入 `Header(...)` 折叠逻辑，现在直接拒绝。

## 保留的关键行为（有意不改动）

- **无条件 `nm = Header(nm, encoding).encode()`**：随附测试要求 `(('A name', 'to@example.com'), 'utf-8')` → `'=?utf-8?q?A_name?= <to@example.com>'`。考古确认这是 3.x 语义；上游 4.2+ 改成 ASCII 优先后期望值变为 `'A name <to@example.com>'`，采纳会直接挂测试。
- **`return str(parsed_address)`**：对全部用例与 `formataddr((nm, parsed_address.addr_spec))` 输出一致，且无需新增 `formataddr` 导入。
- RFC 2047 本地部分（`tó@example.com` → `=?utf-8?b?dMOz?=@example.com`）、IDN punycode（`éxample.com` → `xn--xample-9ua.com`）、带引号本地部分（`"to@other.com"@example.com`）均不变。
