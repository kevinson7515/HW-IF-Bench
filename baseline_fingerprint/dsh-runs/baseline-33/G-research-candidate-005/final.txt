# 端侧小语言模型部署：四类优化的比较与口径辨析

## 0. 核心结论（先给判断）

1. **四类优化作用在不同层面，本质不同**：量化、结构剪枝、知识蒸馏是"改模型"的（改权重/改结构/重新训练出小模型），注意力算子优化是"改算子实现"的（模型权重与质量严格不变）。
2. **四篇论文没有任何一篇直接测过真实端侧设备**。全部性能数字都来自数据中心 GPU（A100 / A5000 / V100）。所谓"端侧适用性"是论文机理上的外推，属于**推断**而非**实测**。这也是本次任务要求区分的关键点。
3. **四篇的性能指标口径互不可比**：加速比（×）、整体时延（秒）、训练天数、HBM 读写量，各不相同，不能直接横向比数字，只能在"机理—瓶颈"层面比较。
4. **一个重要的事实勘误**：语料写"AWQ 论文包含 TinyChat 的部署实验"，但所附 `AWQ.pdf` 是 **arXiv v1（2306.00978v1，2023-06-01）**，全文搜索 `TinyChat` 命中 **0 次**，没有任何端侧板卡（Raspberry Pi / Jetson Orin）实测。TinyChat 端侧数字出现在后续版本（MLSys'24 等）中，**不在本次附件内**，引用时必须注明。

## 1. 量化 —— AWQ（Activation-aware Weight Quantization）

**定位**：训练后（PTQ）低比特**仅权重**量化，不改架构、不反向传播，通过逐通道缩放保护"显著权重"，换取内存占用与访存带宽的下降。

### 论文实测
| 项目 | 口径 |
|---|---|
| 量化格式 | INT3 / INT4，**group-size 128**，仅权重（W3A16 / W4A16），激活保持 FP16 |
| 实验模型 | LLaMA 7B/13B/30B/65B、OPT 125M–66B、指令模型 Vicuna、多模态 OpenFlamingo-9B / LLaVA-13B |
| 校准数据 | Pile 的一个小子集，α、β 在 [0,1] 上网格搜索（20 格） |
| **实测硬件** | 速度：**单卡 80GB A100**（图 6 明确"All numbers are measured on a single 80G A100 GPU"）；量化过程 1–4 张 A100 |
| **质量指标口径** | WikiText-2 **PPL**；MMLU **5-shot** 平均准确率（57 子任务）；CommonSense QA **0-shot** 平均（PIQA/HellaSwag/WinoGrande/ARC-e/ARC-c），用 lm-eval-harness |
| **性能指标口径** | 相对加速比（生成阶段，memory-bound）：**AWQ 4bit 比 3bit GPTQ 快 1.45×**、比带 reorder 的 GPTQ-R 快 2.0×、比 cuBLAS FP16 快 1.85×、比 Triton 实现快 2.4× |

**关键实测数字**：LLaMA-7B INT3-g128，MMLU 5-shot 平均：FP16 38.41% → RTN 33.43% / GPTQ 30.53% / **AWQ 35.43%**；OPT-6.7B INT3 PPL：FP16 12.29 → RTN 43.16 / GPTQ 13.13 / **AWQ 12.99**。加速的物理来源是"反量化后走 **tensor core 的矩阵-矩阵乘**" + 免重排的连续访存。

### 对端侧适用性（**推断**，非实测）
- **机理上成立的推断**：仅权重低比特直接缩小权重体积（~4×），且解码是 memory-bound，端侧同样受带宽/内存约束，因此"降内存→省带宽"的收益方向在端侧成立。论文自己明确写"grouped quantization 是 edge deployment 更实际的设置"。
- **不能直接照搬的推断**：1.45×/1.85× 是 A100 tensor-core 上的数字；端侧 SoC 若无 tensor-core 级单元或不支持高效在线反量化（需 FP16 计算路径），收益会大幅缩水甚至消失。整数-only 加速器上"反量化回 FP16"这条路径根本不存在。**这部分纯属推断，附件内无数据支撑。**

## 2. 结构剪枝 —— LLM-Pruner

**定位**：任务无关（task-agnostic）的**结构化**剪枝，删掉耦合结构（MLP 块/注意力头/通道），再用 LoRA 快速恢复，直接减少参数、MACs 与显存——是四类里唯一同时报"参数/MACs/显存/时延"四项的。

### 论文实测
| 项目 | 口径 |
|---|---|
| 方法 | 依赖检测→基于梯度(一阶+Fisher 近似 Hessian)的重要性估计→LoRA(rank=8)恢复 |
| 实验模型 | LLaMA-7B(→5.4B)、LLaMA-13B、Vicuna-7B、ChatGLM-6B（仍属 7B 级，非"小模型"） |
| 数据 | 校准仅 **10 条**样本(Bookcorpus，seq 128)；恢复用 **50k** Alpaca，2 epoch |
| **实测硬件** | **时延测在单卡 A5000**；恢复在 24GB 卡上（RTX4090 约 2.5h），整体约 3h 单卡 |
| **质量指标口径** | WikiText2 & PTB **PPL**；7 个常识分类（BoolQ/PIQA/HellaSwag/WinoGrande/ARC-e/ARC-c/OpenbookQA）的 **0-shot 平均正确率** |
| **性能指标口径** | 参数量 / MACs / 显存 MiB / **总时延"秒"**（注意：是 64-token 输入、跑完 WikiText2 测试集的总秒数，**不是 tokens/s**） |

**关键实测数字**（表 3，A5000，64 token）：LLaMA-7B 基线 6.74B / 424.02G MACs / 12884.5MiB / 69.32s → Block 20%：5.42B / 339.60G / 10375.5MiB / **58.55s**（~16% 加速）；Block 50%：3.35B / 206.59G / 6533.9MiB / 37.54s。质量：20% 剪枝+恢复后七任务平均 60.07% vs 原模型 63.25%（**94.97% 保留**）。表 13 还给出与 LLM.int8() 组合：显存 6777.7MiB，但时延反而 **76.20s > FP16 的 69.32s**（反量化开销），揭示"降内存≠降时延"。

### 对端侧适用性（**推断**）
- **较可靠的外推**：结构化剪枝删的是整块结构，不破坏规则性，直接降 MACs 与常驻内存，这对内存受限端侧是正面信号，"低数据/3小时"的低资源管线对端侧微调友好。
- **需警惕的推断**：① 实测模型是 6.7B→5.4B，仍远超典型端侧 SLM（≤2B）体量；② 20% 剪枝时延仅降 ~16%（远小于 20% 的 MACs 降幅），因为解码 memory-bound、MACs 下降不能 1:1 变现为端侧时延；③ A5000 是服务器级 GPU，非端侧。**"小而快"的端侧收益是从机理外推，文中未在端侧验证。**

## 3. 知识蒸馏 —— MiniLLM（reverse-KLD 蒸馏）

**定位**：白盒蒸馏，用**反向 KL（KL[q‖p]，mode-seeking）**替代正向 KL，加上 on-policy 策略梯度，是四类里**唯一产出真正"小模型"（student 低至 120M）**、与学生规模最贴近端侧 SLM 的方法。

### 论文实测
| 项目 | 口径 |
|---|---|
| 方法 | 反向 KLD + 策略梯度；单步分解降方差、teacher-mixed 采样(α=0.2)、长度归一化；额外加预训练 LM 损失 |
| 实验模型 | student **120M–13B**：GPT-2 125M/340M/760M（teacher 1.5B）、OPT 1.3B/2.7B/6.7B（teacher 13B）、LLaMA-7B（teacher 13B）、GPT-J-6B 作 teacher |
| **实测硬件** | **V100 32GB**（训练），如 LLaMA-7B←13B "<10 小时 / 16 卡"；**没有任何推理时延/内存测量** |
| 数据集 | DollyEval / SelfInst / VicunaEval / S-NI / UnNI（指令遵循） |
| **质量指标口径** | **Rouge-L**、**GPT-4 feedback 评分（1–10，取与真值之比）**、**人工 Win/Tie/Loss**（SelfInst 50 条）；另测 exposure bias(ExAccErr)、校准、长文本、Dist-4 多样性。解码口径固定为 temperature=1、5 个随机种子、maxlen 512 |

**关键实测数字**：LLaMA-7B←13B：GPT4 评分 76.4 vs SFT 73.0 / KD 73.7 / SeqKD 73.6；OPT-1.3B←13B：60.7 vs 52.6；且从 120M 到 13B 各尺度全面占优、优于人类偏好的基线。语料所写"输出质量与解码设置关联"对应其"temperature=1 + 5 种子"与"按真值长度分桶测 Rouge-L"的分析（长响应上 MiniLLM 优势更明显）。

### 对端侧适用性（**推断**）
- **方向最贴合**：要得到 0.5B–3B 量级的端侧 SLM，蒸馏是最直接路径（120M 起），这是其他三类做不到的。
- **必须澄清的推断**：论文**无端侧部署测量**——不报时延、不报内存、无任何端侧硬件；训练在数据中心 V100 上进行。质量指标是"GPT-4 当裁判"的主观代理分，反映的是**输出质量**而非**端侧可部署性**。"MiniLLM 适合端侧"是"规模能压到小模型"这一点的外推，不是实测结论；且 student 仍需要完整推理运行时，不直接解决算子/内存问题。

## 4. 注意力算子优化 —— FlashAttention（IO-aware exact attention）

**定位**：算子级优化，用 tiling + 反向重算 + 单一 CUDA kernel，避免把 N×N 注意力矩阵写出到 HBM，**精确计算、结果与标准 attention 完全相同**。与前三类正交：它不缩小模型，可叠加在任何已量化/剪枝/蒸馏的模型上。

### 论文实测
| 项目 | 口径 |
|---|---|
| 方法 | IO 感知：减少 GPU HBM↔片上 SRAM 读写；tiling + 反向重算（softmax 归一化因子）；可扩展到 block-sparse |
| 实验模型 | BERT-large、GPT-2 small/medium、Long-Range Arena（ListOps/Text/Retrieval/Image/Pathfinder） |
| **实测硬件** | **A100 GPU**（40–80GB HBM 1.5–2TB/s；每 SM 192KB SRAM≈19TB/s）；CUDA kernel |
| **性能指标口径** | **训练 wall-clock**（非推理、非端侧）：BERT-large 比 MLPerf 1.1 记录快 15%（17.4 vs 20.0 min，8×A100）；GPT-2 比 HF 至多 3×、比 Megatron 1.7–1.8×；LRA 2.4×；attention kernel 本身最高 7.6×；内存**线性**于序列长度。复杂度 O(N²d²/M) vs 标准 Θ(Nd+N²) |
| **质量指标口径** | GPT-2 PPL（4× 上下文下 0.7 提升）、长文档分类（+6.4 分）、Path-X(16K) 61.4% / Path-256(64K) 63.1%（首个优于随机） |

### 对端侧适用性（**推断** + 明确局限）
- 语料已点明"**原论文 GPU 结果受硬件和序列长度约束**"，这正是关键：FlashAttention 的收益**全部来自 GPU 特有的 HBM↔SRAM 存储层级 + 长序列**。
- **不成立的场景**：端侧若没有 GPU 型 SRAM 层级（NPU/CPU 内存模型不同），IO 复杂度的前提不成立；端侧解码是**自回归逐 token 生成、seq 长度逐步 +1**，N×N 矩阵物化问题远不如训练长上下文严重，算子收益很小。**把 A100 上的 7.6×/3× 外推到端侧推理时延是没有依据的推断。**
- **成立但需换口径的场景**：若要跑长上下文、或端侧算力强（移动 GPU），省 HBM/内存带来的收益方向成立，但须在端侧硬件上用端侧序列长度重新测，不能引用原论文数字。

## 5. 横向比较与组合关系

| 维度 | 量化(AWQ) | 结构剪枝(LLM-Pruner) | 知识蒸馏(MiniLLM) | 注意力算子(FlashAttention) |
|---|---|---|---|---|
| 作用层面 | 权重级 | 结构级 | 模型级(重训) | 算子级 |
| 是否改变模型 | 改权重精度 | 删结构 | 换模型 | 不变(精确) |
| 主要瓶颈目标 | 内存/带宽 | 参数/MACs/内存 | 模型规模 | 访存 IO(长序列) |
| 是否为"小模型"产出 | 否(仍 7B 级) | 否(6.7B→5.4B) | **是(低至 120M)** | 否 |
| 实测硬件 | A100 | A5000/RTX4090 | V100(训练) | A100(训练) |
| 端侧是否有实测 | 无(本版无 TinyChat) | 无 | 无 | 无 |

**可组合性**（论文内已有证据）：剪枝 ⊕ 量化可叠加（LLM-Pruner 表 13 已做）；蒸馏产出的小模型可继续量化/剪枝；FlashAttention 与前三者完全正交，可统一作为运行时算子套在任意压缩后的模型上。因此端侧部署的工程化路径通常是"**蒸馏得到小模型 → 结构剪枝 → 权重量化 → 换 IO-aware 算子**"四步叠加，而不是四选一。

## 6. 口径与可信度提醒（汇总）

1. **"性能"不可横比**：四类分别是"相对加速比(A100)"、"总秒数(A5000,64token)"、"训练天数/小时(V100)"、"训练加速比+HBM 读写(A100)"，单位与基线各不相同。
2. **"端侧适用"在四篇里都是推断**：所有数字是数据中心 GPU 的；端侧 latency/吞吐/功耗**零实测**。
3. **质量指标口径差异大且代理性强**：PPL/多选正确率（AWQ、LLM-Pruner）是客观指标，MiniLLM 的 GPT-4 评分是主观 LM-judge；跨方法不能直接比"质量损失"。
4. **版本勘误必须注明**：AWQ 附件为 v1，**不含 TinyChat**；LLM-Pruner 为 v3、MiniLLM 为 v6、FlashAttention 为 v1，引用端侧结论时需确认对应版本。
5. **规模错配**：除 MiniLLM 外，其余三篇的实验主体是 7B 级模型，"端侧小语言模型"的适用性需要重新在 ≤2B 尺度与端侧硬件上验证，不能沿用 7B 结论。
