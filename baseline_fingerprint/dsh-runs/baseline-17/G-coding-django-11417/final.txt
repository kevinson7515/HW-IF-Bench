## What I changed

**`django/core/mail/message.py`**

1. Imported `formataddr` from `email.utils`.
2. Rewrote the tail of `sanitize_address()`:
   - **Newline guard** — concatenates `nm + localpart + domain` and raises `ValueError('Invalid address; address parts cannot contain newlines.')` if it contains `\n` or `\r`, blocking header injection through the tuple form or direct local parts.
   - **Display-name encoding** — only wraps the display name in an encoded word when it isn't pure ASCII; ASCII names are emitted verbatim via `Header(nm).encode()`.
   - **Output** — builds `Address(username=..., domain=...)` and returns `formataddr((nm, parsed_address.addr_spec))` instead of `str(Address(nm, ...))`, which fixes the crash on long (>75 char) display names where the old approach passed an already-wrapped name back into `Address`.

The string/tuple parsing, `email.headerregistry` parsing (`parser.get_mailbox`), IDN handling (`punycode`), local-part MIME-word encoding, and the "not fully parsed" `ValueError` behavior are all preserved.

**`tests/mail/tests.py`** (updated to match the new behavior, mirroring the upstream commit)

- Updated six expected values where ASCII display names are no longer encoded (`A name`, `To Example`, `"to@other.com"`, etc.).
- Added long Unicode display-name cases and a long-name + Unicode-domain case.
- Added `test_sanitize_address_header_injection`.
