# 指令种类说明（生成器修订版 5.10）

当前代码实现 **25 个指令族、46 种策略**。指令族是结果中 `instr_types` 的分类；策略是候选的 `policy.kind`，对应本地模板和评分规则。每个 query 默认生成 5 个变体，可设为 4–6 个；常用模式中每个变体只包含一条独立指令。

## 流程控制类

| 策略 | Agent 需要执行的阶段 | 自动核验 | 启用前提 |
| --- | --- | --- | --- |
| `workflow_locate_read` | 文件定位 → 文件读取 | 首个工具为 `file_glob`/`file_search`，首次 `file_read` 在其后 | 两类工具实际可用，基线首个工具不同 |
| `workflow_workspace_read` | 环境检查 → 文件读取 | 首个工具为 `cwd_inspect`/`sandbox_prepare`，首次 `file_read` 在其后 | 两类工具实际可用，基线首个工具不同 |
| `workflow_search_fetch` | 来源搜索 → 网页抓取 | 首个工具为 `web_search`，首次 `web_fetch` 在其后 | 两类工具实际可用，基线首个工具不同 |
| `workflow_locate_read_run` | 文件定位 → 文件读取 → 执行处理或验证 | 三种阶段工具的首次调用按顺序出现 | 定位、读取、执行工具实际可用，基线首个工具不同 |
| `workflow_workspace_locate_read` | 环境检查 → 文件定位 → 文件读取 | 三种阶段工具的首次调用按顺序出现 | 环境、定位、读取工具实际可用，基线首个工具不同 |
| `workflow_plan_locate_read` | 任务规划 → 文件定位 → 文件读取 | 三种阶段工具的首次调用按顺序出现 | 规划、定位、读取工具实际可用，基线首个工具不同 |
| `workflow_catalog_first` | 先查真实工具目录，再开展任务 | 首次工具调用名称 | 有可用目录工具及基线首调差异 |
| `workflow_plan_first` | 先调用任务规划工具，再开展任务 | 首次工具调用名称 | 有 `task_planning` 及基线首调差异 |
| `workflow_plan_progress` | 先展示计划，每三次工具调用更新进度 | 有序可见消息与工具事件 | 已实现 `trace.events` 适配器 |
| `workflow_readonly_probe` | 先只读探查，再进行可能的修改 | 有序副作用事件 | 已实现 `trace.events` 适配器 |
| `workflow_tool_discovery` | 先查询目录并说明后续工具选择 | 目录调用和可见说明 | 已实现 `trace.events` 适配器 |
| `workflow_approval_gate` | 写入前列文件清单并等待真实确认 | 请求、确认、写入事件 | 已实现交互与 `trace.events` 适配器 |

前六种是多阶段流程，只依赖本次变体回放中的有序工具名；它们**不能**仅凭工具名证明找对文件、抓到有效内容或完成原任务。后四种涉及可见消息、操作副作用或用户确认，在缺少真实适配器时不会强行生成。原有 `first_round_readonly` 也属于过程类，需要专用运行证据。

有足够候选时，5 个变体目标选择 2 条不同流程；证据不足时降低占比。一次内部 50 任务生成得到 59/250（23.6%）条流程变体、23 种不同文本。实际占比取决于输入任务的工具和 fingerprint；生成结果仍需真实回放和人工复核。

## 其他类别

输出与布局、工具预算与顺序、代码与产物、引用和来源、条件分支、证据关联等策略仍可用。全部策略名称及参数以 [policy_catalog.json](policy_catalog.json) 为准；实现分别位于 `base_policies.py`、`policies.py`、`workflow_policies.py`。生成流程和输入要求见 [README.md](README.md)，事件适配器要求见 [WORKFLOW_CONTRACT.md](WORKFLOW_CONTRACT.md)。

类别数量表示代码能力，不表示每个任务都能使用全部类别。候选必须有外部提供的 fingerprint、真实工具及相应运行证据支持，并通过本地规则与独立语义审查；发布前还需实际回放和人工复核。
