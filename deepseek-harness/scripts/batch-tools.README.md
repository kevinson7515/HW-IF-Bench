# Cluster batch tools

English | [中文](batch-tools.README.zh.md)

## Summary

`run.sh` runs headless JSONL tasks with the company DeepSeek or GLM route or the private Pangu route. It selects Serper for `web_search` and exposes E2B Python execution and file export through `batch-tools.patch.yml`. Pangu batches also receive `mcp__vision__inspect_image`, which sends an exported repository image to the company DeepSeek route and returns a text observation. The E2B bridge runs as an MCP process; its sandbox persists for calls within one task and closes when that task ends.

## Model provider

The default `sbatch run.sh` runs `user_query.jsonl` with company DeepSeek. The [benchmark guide](benchmark.README.md#submit) owns the model-specific benchmark wrappers. Deployment templates live in `scripts/config/`; place them under `$WORK/dsh-config/` without embedding credentials.

| Provider | Model | Patch under `$WORK/dsh-config/` | Key under `$WORK/.secrets/` |
|---|---|---|---|
| `company-deepseek` (default) | `deepseek-v4-pro` | `deepseek.patch.yml` | `deepseek-api-key` |
| `company-glm` | `glm-5.3` | `glm.patch.yml` | `glm-api-key` |
| `pangu` | `openPangu-v21-pro` | `pangu.patch.yml` | `pangu-api-key` |
| `pangu92b` | `pangu92b_wandr` | `pangu92b.patch.yml` | `pangu92b-api-key.yml` |

DeepSeek and GLM default to `http://115.120.87.159:8082/v1`, overridden separately by `COMPANY_DEEPSEEK_BASE_URL` and `COMPANY_GLM_BASE_URL`. Pangu defaults to `http://101.245.71.190:9080/v1`, overridden by `PANGU_BASE_URL`. All use Chat Completions with Bearer authentication. Keys load into `COMPANY_DEEPSEEK_API_KEY`, `COMPANY_GLM_API_KEY`, or `PANGU_API_KEY`; an explicitly exported value overrides its file. `DSH_API_KEY_FILE` overrides the selected model's key path; `DSH_PATCH_FILE` overrides its patch. Pangu no longer reads hardware/app credentials. Its separate vision credential loads from `deepseek-api-key` or `DSH_VISION_API_KEY_FILE`, never from the Pangu key override. `DSH_COMPANY_API_NO_PROXY=1` bypasses the HTTP proxy for the selected API and, for Pangu, the company vision API. HTTP endpoints do not encrypt credentials or task contents.

The Pangu deployment retains a 524,288-token context and 32,768-token output capacity; these values are not verified for the new gateway. Override `PANGU_CONTEXT_WINDOW` and `PANGU_MAX_TOKENS` with accepted values if needed. Compaction retains 4,096 tokens of headroom and a 2,048-token summary cap, controlled by `PANGU_COMPACTION_HEADROOM_TOKENS` and `PANGU_COMPACTION_MAX_TOKENS`. Stream timeouts are unchanged. The script selects Conda's `certifi` CA bundle for Pangu's HTTPS tool requests when `SSL_CERT_FILE` is unset or unreadable inside Singularity; it preserves a readable custom bundle.

Pangu's `retryPolicy` under `llm-pi-ai.config.providers.pangu` uses bounded `normal` mode with eight retries after the initial attempt. Local backoff starts at 10 seconds, doubles, and caps each wait at 120 seconds with 10% jitter: nominal waits are 10, 20, 40, 80, 120, 120, 120, and 120 seconds, totaling about 10.5 minutes excluding request durations. Provider retry-after hints can change that timing under the existing retry rules. Exhaustion remains a failed task; cancellation still interrupts waits. The default transient error codes, including `RATE_LIMIT`, are unchanged; authentication and invalid-request errors do not become retryable. DeepSeek and GLM retain their existing policies. This does not raise the gateway's quota or guarantee recovery. Copy the updated `scripts/config/pangu.patch.yml` to `$WORK/dsh-config/pangu.patch.yml`; editing the repository template alone does not change the deployed patch. No build or launcher changes are required.

Pangu92B is a separate Huawei route at `https://apigw-dgg-b0.huawei.com/api/pangu/v1`, overridden by `PANGU92B_BASE_URL`. Its `.yml` credential file must use JSON object syntax (a YAML subset) with nonempty single-line ASCII `api_key`, `hw_id`, and `hw_app_key` strings. Keep it owner-only (`chmod 600`); unlike the other models' key files, it is not a raw token line. The loader sets `PANGU92B_API_KEY`, `PANGU92B_HW_ID`, and `PANGU92B_APP_KEY`; exported values override the corresponding fields, and exporting all three avoids reading the file. The provider sends Bearer authentication plus `X-HW-ID` and `X-HW-AppKey`. Do not publish a resolved configuration: custom header values can include credentials. Defaults are a 262,144-token context, 32,768-token output, 4,096-token compaction headroom, and 2,048-token summary; these deployment settings are not verified limits of the private alias. Override them independently with `PANGU92B_CONTEXT_WINDOW`, `PANGU92B_MAX_TOKENS`, `PANGU92B_COMPACTION_HEADROOM_TOKENS`, and `PANGU92B_COMPACTION_MAX_TOKENS`. Existing request timeouts and the harness's default retry policy are unchanged. Like Pangu, it uses the DeepSeek vision credential and certifi fallback; the existing `pangu` provider remains independent and does not acquire Huawei headers.

## Setup

Install `e2b-code-interpreter` and `certifi` into the Conda environment that `run.sh` activates. Serper and E2B default to the owner-only `$WORK/.secrets/serper-api-key` and `$WORK/.secrets/e2b-api-key` files. Override them with `DSH_SERPER_API_KEY_FILE` and `DSH_E2B_API_KEY_FILE`, or export the corresponding variables before submission. Each key file contains one nonempty line; Windows CRLF and a UTF-8 BOM are removed when reading, while embedded newlines are rejected before API use. The script does not store keys in its configuration files.

The Serper gateway defaults to `https://yibuapi.com`, with text search at `/serper/search` and image search at `/serper/images`. Set `SERPER_BASE_URL` to change its origin and `SERPER_AUTH_MODE` to `bearer`, `x-api-key`, or `auto` (the default). The patch enables `image_search` while retaining the existing search result cap and timeout; images are returned as links, not downloaded bytes.

E2B uses the official service with `E2B_API_KEY`. `E2B_PROXY` defaults to the batch HTTP proxy. The adapter sets `SSL_CERT_FILE` from `certifi` and uses the SDK's request-timeout default; the MCP client retains its own configured call timeout. It does not disable certificate checks or use the Serper gateway as an E2B base URL.

### E2B attachments and dependencies

An explicitly attached empty regular `.keep` file is the only hidden-filename exception. Its parent directories must pass the ordinary input checks; nonempty placeholders and symbolic links are rejected. Project-tree discovery still skips hidden files.

Both batch runners pass the current task's recorded `task.json` to the E2B bridge through `DSH_E2B_TASK_FILE`. Before `execute_python`, the bridge uploads its declared attachments and explicitly configured project sources using E2B's [file API](https://docs.e2b.dev/filesystem/read-write), then checks their SHA-256 inside the sandbox. Linux repository paths are mirrored at the same absolute paths; the first preparation sets the kernel's working directory and import path to the mirrored repository. Windows development checks use `/home/user/dsh-workspace`, and tool metadata reports the mapping. Local attachments are authoritative and recopied before each execution, so local file-tool edits are visible to subsequent E2B calls; edits made only to remote attachment copies are not imported back and are overwritten on the next sync. The existing export tool still never overwrites local files. Hidden paths, credentials, dependency trees, symlinks, and paths outside the repository are rejected. Input limits default to 100 MiB per file and 256 MiB total (`DSH_E2B_MAX_INPUT_FILE_BYTES`, `DSH_E2B_MAX_INPUT_TOTAL_BYTES`).

`DSH_E2B_PROJECTS_FILE` defaults to `scripts/config/e2b-projects.json`. A profile matches task attachments by repository-relative `attachment_prefix`; `packages` supplies pip requirements and `imports` supplies modules whose availability must be checked. Preparation uses the kernel's `sys.executable`, only inside E2B, and runs once per task. The shipped Astropy profile uses the recorded compatibility versions `astropy==8.0.2` and `numpy==2.3.5` plus pytest. The Django profile installs unpinned Django and pytest because the original version is unavailable. Neither reconstructs a historical project baseline. The report includes actual Python, distribution versions, import locations, and a remote `.dsh-e2b-installed.json` file with all installed distribution versions. Use `mcp__e2b__prepare_environment` to inspect this report without running task code; `execute_python` also includes it in its logged result.

For a supplied full project, set a profile's repository-relative `project_dir` to synchronize its non-hidden source tree, `requirements_files` to upload and install explicit requirements files, and `install_project: true` to install that synchronized project in editable mode. Editable installation requires `pyproject.toml` or `setup.py`; sparse source snippets are refused as installable projects. A dependency configuration or requirements-file change after preparation requires a fresh task. A custom `DSH_E2B_TEMPLATE` can select a prepared sandbox runtime when older packages require another Python version. Upload, integrity, installation, or declared-import failures block task code and remain visible; restart the task after repairing its setup. Sandbox lifetime, SDK/MCP timeouts, model retries, and scoring are unchanged.

Sparse attachments plus importable dependencies do not constitute a runnable original test suite. Importing the installed Astropy or Django package does not test the edited attachment files; use the reported paths and hashes to identify the code actually exercised. No complete original source or lock files are supplied with these two tasks, so full historical regression validation remains unavailable. Synchronize updated `run.sh`, `batch-tools.patch.yml`, `scripts/run-benchmark.py`, `scripts/dsh-e2b-mcp.py`, `scripts/dsh_e2b_environment.py`, and `scripts/config/e2b-projects.json` together; no Node build is required. Offline checks are `python scripts/test-e2b-mcp.py` and `python scripts/test-benchmark.py`. The source-profile composition smoke, enabled with `DSH_BENCHMARK_TEST_NODE`, checks a real headless Session containing E2B metadata for a locally edited attachment; only model and E2B network endpoints are simulated. These checks do not establish live pip or E2B availability.

The Pangu-only vision tool accepts an existing PNG, JPEG, or WebP file inside the repository after E2B export. It sends image bytes and a focused question to `DSH_VISION_MODEL` (default `deepseek-v4-pro`) at `COMPANY_DEEPSEEK_BASE_URL` (default `http://115.120.87.159:8082/v1`) using Chat Completions, and returns only the other model's text observation. `DSH_VISION_TIMEOUT_SECONDS` defaults to 180, `DSH_VISION_MAX_TOKENS` to 4096, and `DSH_VISION_MAX_IMAGE_BYTES` to 8 MiB; the MCP call allows ten extra seconds beyond the HTTP timeout. The tool does not expose the company key to the Pangu prompt or E2B sandbox. The default company URL uses unencrypted HTTP, so the key and image bytes are not protected in transit; use an HTTPS endpoint when available. A successful text-only DeepSeek request does not establish image support: if the company gateway rejects image input, the tool reports an error instead of claiming inspection.

## Run and verify

Submit from the repository root with `sbatch run.sh` for company DeepSeek JSONL tasks or the model-specific benchmark wrapper. Before submitting, run `python scripts/test-e2b-mcp.py` and `python scripts/test-vision-mcp.py` for offline adapter checks and `bash -n run.sh` on Linux for shell syntax. The offline tests do not validate live services; verify the new Pangu gateway's token limits and the company DeepSeek gateway's image support with a small live batch before a full evaluation. Pangu needs readable, owner-only `pangu-api-key`, `deepseek-api-key`, `serper-api-key`, and `e2b-api-key` files under `$WORK/.secrets/`. Check the logged provider and patch path, then `results.jsonl` in the records directory for outcomes. Unset obsolete exported endpoint/key/patch overrides before changing deployments; the scripts preserve explicit overrides.

The `mcp__e2b__execute_python` tool returns logs, errors, and display results. Files created in E2B are not local until `mcp__e2b__export_file` copies one to a new repository-relative path, for example `remote_path=/home/user/chart.png` and `local_path=stock-analysis/chart.png`. The export streams bytes directly from the same task's sandbox, returns path/size/SHA-256 metadata rather than file content, and never overwrites an existing local file. It rejects parent-directory traversal and symbolic-link directories. `DSH_ARTIFACT_MAX_FILE_BYTES` also limits each E2B export (default 100 MiB); exported files remain in the task's chosen repository location and are included in the batch artifact copy. The batch script requires native tool mode, disables local Bash execution, and leaves local filesystem tools in place.

For a Pangu task, call `mcp__vision__inspect_image` with the exported local path and a specific visual question, such as whether the K-line chart labels are clipped. The tool refuses paths outside the repository, hidden or dependency files, unsupported image bytes, and oversized files. Its answer is evidence from a second model, not a replacement for checking data calculations or an instruction source for Pangu. Do not call `read_image` on the text-only Pangu route; `image_search` returns links rather than inspection of local images.
